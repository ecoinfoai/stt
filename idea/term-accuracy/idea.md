# 전문용어 전사 정확도 관리

## Background

stt는 용어사전을 받아 전문용어 인식을 돕지만, 인식 엔진이 받아들이는 용어 분량에는 고정 한도(223토큰, 짧은 용어 약 40개)가 있고
넘친 용어는 아무 표시 없이 버려진다. 지금 `terms.txt`는 137개·818토큰이라 앞쪽 약 27%만 실제로 쓰인다(2026-10-04 처음 발견, 10-15 재확인).
반면 한도 안에 맞춘 감염미생물학 사전(42개·219토큰)은 수업 녹음 16건 재전사에서 추적한 오기를 352건 → 137건으로 줄였다.
남은 오기의 대부분은 '간염'이다. 발음이 [가념]이고 흔한 단어 '감염'과 겹쳐, 사전을 넣어도 104건 → 113건으로 줄지 않았다.

## Problem

- **운영자(교수)**는 용어사전이 얼마나 반영되는지 알 수 없다. 137개를 넣고도 앞쪽 37개만 쓰였다는 사실을 토큰을 직접 세어 보고서야 알았다.
- 사전으로 고쳐지지 않는 반복 오기(간염 → "간념", "C형 관념", "B형 감염")가 16건에서 110건 넘게 남는다. 손으로 고치기에는 양이 많다.
- 사전이나 규칙을 바꿨을 때 정말 나아졌는지 확인하려면 매번 비교 스크립트를 즉석에서 짜야 한다. 실제로 간염처럼 사전을 넣고도 나빠진 경우가 있었다.

## Desired Outcome

운영자는 전사를 시작하기 전에 용어사전이 몇 개나 반영되는지 안다.
사전으로 안 되는 반복 오기는 전사 결과에서 자동으로 바로잡히고, 무엇이 바뀌었는지는 기록으로 남는다.
사전이나 규칙을 바꾼 효과는 같은 녹음의 이전 결과와 비교한 수치로 확인한다.

### User Scenarios

- **운영자(교수)**는 과목 용어사전이 실제로 몇 개 반영되는지 전사 시작 전에 알고 싶다. 왜냐하면 지금은 대부분이 버려져도 아무 표시가 없어, 효과가 있는 줄 알고 쓰게 되기 때문이다.
- **운영자**는 '간염'처럼 사전으로 고쳐지지 않는 오기를 전사 단계에서 한꺼번에 바로잡고 싶다. 왜냐하면 녹음 16건에 110건 넘게 나오는 오기를 손으로 고칠 수는 없기 때문이다.
- **보고서 작성자(운영자 본인)**는 전사문의 어느 곳이 자동 교정됐는지 확인하고 싶다. 왜냐하면 전사문을 원문 인용의 근거로 쓰므로, 인용한 문장이 들린 그대로인지 교정된 것인지 구분해야 하기 때문이다.
- **운영자**는 용어사전이나 교정 규칙을 바꾼 뒤 실제로 나아졌는지 용어별 숫자로 확인하고 싶다. 왜냐하면 사전을 넣어도 나아지지 않거나 오히려 나빠지는 용어가 있기 때문이다.
- **bhu-llm 이용자(교수·직원)**는 단어장을 올린 뒤 "반영 N개 / 전체 M개"를 보고 싶다. 왜냐하면 단어장이 한도를 넘었는지 알아야 고쳐 올릴 수 있기 때문이다(bhu-llm 핸드오프 S9).

## Constraints

- 원문 인용 무결성: 자동 교정은 반드시 내역이 남아야 하고, 내역만으로 교정 전 전사문을 그대로 복원할 수 있어야 한다. 전사문이 보고서의 원문 인용 근거이기 때문이다.
- 오교정 금지: '감염', '관념', '분명'처럼 정상 문맥에서도 쓰이는 일반어는 무조건 바꾸지 않는다. 수업 전사문에서 이런 단어가 정상으로 쓰인 경우가 수십 건 확인됐다.
- 한도 초과 시 경고 후 계속: 반영 수와 빠진 용어를 보여 주고 전사는 진행한다. 파일 순서가 곧 우선순위인 지금 방식과 기존 `terms.txt`를 그대로 쓸 수 있어야 하기 때문이다.
- 기존 사용 호환: 용어사전 형식(한 줄에 하나, `#` 주석)과 지금의 명령은 바뀌지 않고 동작해야 한다.
- 로컬 처리: 음원과 전사는 기기 밖으로 나가지 않는다.

## Success Criteria

- SC-1: 한도를 넘는 용어사전으로 전사를 시작하면, 시작 전에 "반영 N개 / 전체 M개"와 빠지는 용어 목록이 표시된다. 현재 `terms.txt`로 시험하면 "반영 37개 / 전체 137개"가 표시되고, 38번째 '지식인사이드'부터 빠진 용어로 나열된다(2026-10-15 실측).
- SC-2: 용어사전을 쓴 모든 전사 결과의 기록에 사용한 사전, 반영 용어 수, 전체 용어 수가 남는다(100%).
- SC-3: 2026-10-15 재전사본 16건에 교정 규칙을 적용하면 간염 오기 형태가 0건이 된다. 대상은 "간념", 그리고 'A형~E형' 뒤에 붙은 "관념"·"감염"(예: "C형 관념", "B형 감염")이다. 정상 문맥의 '감염'(예: 비말감염, 감염경로)은 1건도 바뀌지 않는다.
- SC-4: 교정된 모든 위치가 문단 시각, 교정 전, 교정 후, 적용 규칙과 함께 기록에 남는다. 기록으로 복원한 전사문이 교정 전 전사문과 글자 하나까지 같다.
- SC-5: 같은 녹음의 이전 전사본과 새 전사본을 비교하면 용어별 오기 증감과 전체 분량 변화가 한 번에 보고된다. 2026-10-15 수작업 비교 결과(352 → 137, 간염 제외 248 → 24)가 그대로 재현된다.

## Discussion Notes

> - 2026-10-04 세션에서 용어 한도 문제를 처음 찾았고 세 가지 안이 나왔다: (a) 강연별 짧은 사전, (b) 강연 정보로 용어 자동 선별, (c) 한도 초과 경고. (a)는 기존 목록 파일의 항목별 옵션으로 이미 가능하다. 이번에는 (c)에 반영 수 기록을 더했고, (b)는 범위에서 뺐다.
> - 2026-10-15 미생물학 사전은 이렇게 만들었다. 16건 전사문에서 오기를 모아 '오기 횟수 ÷ 토큰 비용' 순으로 42개를 골랐고, 2건으로 먼저 비교한 뒤 16건 전체를 다시 전사했다. 사전 용어가 들리지 않은 곳에 끼어든 흔적은 없었고, 분량 변화는 ±1.2% 이내였다.
> - '간염'은 사전으로 고칠 수 없다고 판단했다. 그래서 결정론적 교정 규칙을 택했다. 교정 규칙은 2026-10-04에 '후처리 교정 사전'으로 처음 제안됐다.
> - 기각한 안 ①: 한도 초과 시 에러로 멈추기. 기존 `terms.txt`를 쓸 수 없게 되고, 파일 순서가 우선순위인 방식과 맞지 않는다.
> - 기각한 안 ②: 교정을 제안만 하기. 110건 넘는 오기를 사람이 검토하는 것은 비현실적이다. 대신 교정 내역 기록으로 추적성을 확보한다.
> - 범위 밖: LLM 교정(원문 인용 무결성과 충돌하므로 하더라도 검토용 diff로만), 정밀도·무음 구간·한국어 특화 모델 실험, 서버 연동 자체(별도 아이디어 문서 `server-transcription`).
