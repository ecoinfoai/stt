# Contextual Biasing for Whisper / End-to-End ASR and the Effect of Biasing-List Size

Scope note: these notes cover model-side biasing (prompting, keyword-spotting-then-prompting, trained biasing modules, decoding-time boosting) and evidence on list size and distractors. Post-hoc text correction is out of scope except where it bears on a model-side limit.
Source labels: **[peer-reviewed]** = conference or journal paper; **[preprint]** = arXiv only, venue not verified; **[practitioner]** = GitHub issues/PRs, vendor docs, cookbooks (not peer-reviewed); **[code]** = source code read directly.
All PDFs were read in full text (pdftotext), not through summaries. One summarizer output for arXiv 2508.17796 invented numbers ("~12–15% baseline WER", "diminishing returns beyond 500–1,000 terms"), so it was thrown out and every number below comes from the paper's own tables.

## Q1. How do Whisper prompting and faster-whisper `hotwords` bias decoding? (length limits, ordering, hallucination, rare-word gains)

### Takeaway
A Whisper prompt is text placed in the "previous transcript" slot (`<|startofprev|> … <|startoftranscript|>`). It acts as a soft lexical/style prior, not an instruction, and it cannot override what the audio says. A short, relevant list cuts rare-word errors a lot (≈25–45% relative B-WER/R-WER in English benchmarks). The same prompt often raises errors on common words (U-WER) and on spontaneous or non-English speech. It can also make the model hallucinate the prompted terms, on silence or when only true terms are listed. faster-whisper's `hotwords` is the same mechanism re-applied to every 30-s window. It truncates at the **tail** (keeps the first 223 tokens), while openai-whisper's `prompt` keeps the **last** 223 tokens.

### Cited Findings
**Mechanism and limits (code / docs)**
- faster-whisper v1.2.1 `get_prompt()`: if `hotwords` is set and no `prefix` is given, the prompt is `[sot_prev] + encode(" " + hotwords.strip())`. When the encoded length is `>= max_length // 2` (448//2 = 224), it is cut to `hotwords_tokens[: max_length // 2 - 1]`, i.e. **the first 223 tokens are kept and the tail is dropped**. Previous-text tokens, if any, are appended after the hotwords with their own cap `previous_tokens[-223:]`. Hotwords "have no effect if prefix is not None" (local `faster_whisper/transcribe.py` lines 1532–1566, 345–346; `self.max_length = 448` at line 722) — [code] [faster-whisper transcribe.py](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)
- With `condition_on_previous_text=False`, faster-whisper sets `prompt_reset_since = len(all_tokens)` after every window (lines 1372–1382). `initial_prompt` tokens are added to `all_tokens` once at the start (lines 1143–1149), so they affect only the first window, whereas `hotwords` goes into every window's prompt — [code] [faster-whisper transcribe.py](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)
- PR #731 ("Feature/add hotwords", merged 2024-05-04) states its reasons: `initial_prompt` "only applies to the first window"; the hotwords approach "add[s] hotword-related prompts before each transcription window" and "occup[ies] the space previously used by the prefix" — [practitioner] [SYSTRAN/faster-whisper PR #731](https://github.com/SYSTRAN/faster-whisper/pull/731)
- openai-whisper `DecodingTask._get_initial_tokens`: `[sot_prev] + prompt_tokens[-(self.n_ctx // 2 - 1):] + tokens`, i.e. **it keeps the last 223 prompt tokens**. `sample_len` defaults to `n_text_ctx // 2` — [code] [openai/whisper decoding.py](https://github.com/openai/whisper/blob/main/whisper/decoding.py)
- OpenAI's prompting guide: "the prompt is limited to only 224 tokens. If the prompt is longer than 224 tokens, only the final 224 tokens of the prompt will be considered; all prior tokens will be silently ignored." Whisper "follows the style of the prompt, rather than any instructions contained within." "The prompt will not override the model's comprehension of the audio." Short prompts make style-following less reliable. Simple name lists and sentence-style prompts both fixed misspelled names in their examples — [practitioner] [OpenAI Cookbook: Whisper prompting guide](https://developers.openai.com/cookbook/examples/whisper_prompting_guide)
- Jogi et al.: the biasing list "is limited to 70 for Whisper since by default it allows a maximum of 224 tokens as input for prompt, which approximates to around 70 words" (English) — [preprint] [Jogi et al. 2025, arXiv:2502.11572](https://arxiv.org/abs/2502.11572)

**Gains and costs of plain list prompting (English benchmarks)**
- Whisper-large with a prompted list (N=70 incl. distractors), averaged over 11 English test sets: R-WER 23.7 → 18.0%, OOV-WER 60.0 → 37.1%. But **U-WER rose 9.1 → 11.6%** and average WER rose 10.3 → 12.1%. WER got worse on 6/11 sets, badly on spontaneous/conversational sets: CHiME-6 25.3 → 32.5, CORAAL 19.7 → 28.3, TED-LIUM 4.6 → 8.3. The authors attribute this to the prompt being "misaligned for the instruction of contextual biasing", because Whisper expects the previous segment's transcript — [preprint] [Jogi et al. 2025](https://arxiv.org/abs/2502.11572)
- Whisper-turbo on LibriSpeech with the IS21 rare-word list, naive comma-separated prompt, N=100 distractors: B-WER 10.4 → 7.8 (test-clean) and 19.7 → 15.2 (test-other); WER 3.2 → 2.7 — [peer-reviewed] [Hou et al., Interspeech 2025, doi:10.21437/Interspeech.2025-646](https://www.isca-archive.org/interspeech_2025/hou25_interspeech.pdf)
- **Oracle list (only the true bias words, no distractors)**: B-WER fell to 5.59/10.02, but **WER rose 3.23 → 4.93 (clean) and 5.33 → 7.64 (other)**, which the authors attribute to "the hallucination phenomenon" — [peer-reviewed] [Hou et al. 2025](https://www.isca-archive.org/interspeech_2025/hou25_interspeech.pdf)
- **Word order matters**: N=100, true words placed at the end of the list ("ascending" score order) gave B-WER 5.73/10.15, random order 7.78/15.21, true words first 10.03/19.44. "the model performs best when the true bias words are placed at the end of the list" — [peer-reviewed] [Hou et al. 2025](https://www.isca-archive.org/interspeech_2025/hou25_interspeech.pdf)
- Prompt style: a "spoken-style" template ("The topic of today's speech is, ah, {w1, w2, …}. Okay, then I'll continue.") did slightly worse than the naive list on LibriSpeech at N=100: B-WER 8.30 vs 7.78 — [peer-reviewed] [Hou et al. 2025](https://www.isca-archive.org/interspeech_2025/hou25_interspeech.pdf). On spontaneous Chinese/English technical talks, CB-Whisper found the reverse: spoken-form prompts consistently beat naive prompts. The naive list made Whisper "omit filler words and disfluencies" and could raise MER above the no-prompt baseline. Example: Whisper-medium Internal-2 MER 6.7 (no prompt) → 14.6 (naive) → 4.8 (spoken form) — [peer-reviewed] [Li et al., CB-Whisper, LREC-COLING 2024, arXiv:2309.09552](https://arxiv.org/abs/2309.09552) / [ACL Anthology](https://aclanthology.org/2024.lrec-main.262)
- Keyword prompts from a KWS front-end fed to an off-the-shelf Whisper-large-v2 (20 queried keywords, 3 true): VoxPopuli WER 13.39 → 16.70 (keyword F1 81.77 → 83.77); **Medical WER 7.33 → 32.82**, F1 80.50 → 68.71; UWB-ATCC WER 76.55 → 55.27. Prompt-tuning just 15K parameters (KG-Whisper-PT) instead gave Medical WER 6.15 / F1 96.58 — [preprint] [Shamsian et al. 2024, Keyword-Guided Adaptation of ASR, arXiv:2406.02649](https://arxiv.org/abs/2406.02649)
- Japanese domain dictionaries (47–157 terms) given as an initial prompt to Whisper-medium: HGP CER 14.97 → 12.05 and dictionary recognition rate (DRR) 78.82 → 81.09; GPT-Syn DRR 16.95 → 59.32. The authors note the prompt "is short (less than 250 tokens) and faces a challenge with a long dictionary" — [peer-reviewed] [Nguyen et al., SIGDIAL 2024](https://aclanthology.org/2024.sigdial-1.42.pdf)

**Does Whisper "understand" prompts?**
- Topic prompts with *mismatched* (wrong) topics often helped as much as matched ones. The best mismatched prompt improved up to 11% relative over the matched one. "textual prompts that make sense to humans do not always bring improvements". English prompts generally beat Mandarin prompts even on Mandarin data — [preprint] [Yang, Huang, Lee 2024, "Do Prompts Really Prompt?", arXiv:2406.05806](https://arxiv.org/abs/2406.05806)
- Peng et al. (Whisper zero-shot AVSR via CLIP-retrieved object words put in the prompt): with the English-only model on their How2 tuning set, "using very large number of objects (as many as 90 objects) does not hurt performance", even with many irrelevant words, so Whisper is "very robust to the noise and length of the prompt". But the same visual prompt **hurt the multilingual Medium, Large and Large-V2** models while helping English-only models. Medium.en improved 9% on VisSpeech — [peer-reviewed] [Peng et al., Interspeech 2023, arXiv:2305.11095](https://arxiv.org/abs/2305.11095)

**Hallucination of prompted terms (practitioner)**
- faster-whisper issue #1356: with Korean `hotwords="수술 모드, 진료 모드 종료, 체어 정위치"`, silent input produced "수술 모드, 진료 모드, 진료 모드, …". The maintainer replied: "That's expected hallucination on silence, try `vad_filter=True`" — [practitioner] [SYSTRAN/faster-whisper #1356](https://github.com/SYSTRAN/faster-whisper/issues/1356)
- faster-whisper issue #1076: a maintainer reports hotwords "worked as expected on several models, although smaller models were less affected" — [practitioner] [SYSTRAN/faster-whisper #1076](https://github.com/SYSTRAN/faster-whisper/issues/1076)

### Inferences
- **Truncation direction matters for ordering.** Hou et al. found true terms work best at the end of the list. In faster-whisper the end is exactly what gets cut when the list is over 223 tokens, while openai-whisper cuts the beginning. So in faster-whisper, keep the encoded hotwords strictly ≤ 223 tokens and then put the highest-priority terms last. (Interpretation. Hou et al. did not test faster-whisper.)
- Hou et al.'s IS21 N=100 English list almost certainly exceeds 224 tokens once each rare word is BPE-tokenized (the paper does not report prompt token counts). If their implementation truncated like openai-whisper (keep the last tokens), then "true words at the end works best" and "N ≥ 500 gives no gain" may partly reflect true words being truncated away, not only attention dilution. Treat their large-N prompt numbers as "prompt overflow" behavior. (Interpretation; the paper does not state the truncation behavior.)
- Your setting (condition_on_previous_text=False, so hotwords are the whole prompt, ~40 Korean terms, spontaneous lectures) resembles the conditions that showed U-WER and hallucination costs: CORAAL/CHiME-6 in Jogi et al., spontaneous talks in CB-Whisper. Your 352 → 137 tracked-error reduction (−61%) matches the literature's "domain terms gain most" finding (Sun et al. 2023, below). Measuring only tracked terms, however, would miss any U-WER rise or insertions. Plan to check untracked-word WER and insertions of listed terms, especially in silent or low-speech regions.
- A spoken-form Korean template (e.g., "오늘 강의 주제는, 음, A, B, C입니다. 자, 계속하겠습니다.") is worth an A/B test given CB-Whisper's spontaneous-speech results. It costs tokens from the 223 budget, and Hou et al. show it can be neutral or negative on read speech. (Interpretation.)

### Gaps
- No peer-reviewed study measured how faster-whisper `hotwords` specifically (per-window repetition, tail truncation) changes results compared with openai-whisper prompting.
- No peer-reviewed study quantified the "prompted-term insertion rate" (hotword hallucination per hour of audio) as a function of list size. Evidence is anecdotal (issue #1356) or indirect (Hou et al.'s oracle-list WER rise).
- Prompt-token cost of Korean terms: no paper reports Whisper BPE token counts for Korean terminology. Your 2–10 tokens/term figure is a local measurement.

## Q2. Keyword-spotting-then-prompting (CB-Whisper and similar): details, numbers, compute

### Takeaway
Pre-selecting a small relevant subset of a large entity list with an audio-side scorer (TTS-synthesized references compared against Whisper-encoder features, or a phonetic retrieval module) and prompting only that subset is currently the best-documented way to scale prompt biasing past the 224-token limit with a **frozen** Whisper. Reported gains are large (entity recall roughly 80–87% → 97%; B-WER −40% versus prompting the full list). All published selectors are **trained modules**: small CNNs or cross-attention scorers trained on a few hundred hours. No off-the-shelf Korean selector exists.

### Cited Findings
- **CB-Whisper** (Huawei): TTS (edge-tts) renders each entity. The entity audio and the utterance pass through the Whisper encoder, a weighted sum of multi-layer features is taken, and an utterance × entity cosine-similarity matrix is computed. A 4-layer CNN (128/128/256/256 channels, kernel 3, about 0.2M params) classifies presence. Cost is "linear computational complexity to the number of keywords", batchable on GPU. No latency numbers are reported — [peer-reviewed] [Li et al. 2024, arXiv:2309.09552](https://arxiv.org/abs/2309.09552)
- CB-Whisper training: the KWS was trained on Aishell-1 (150 h), LibriSpeech train-clean-100, and TALCS (578 h). A multitask variant fine-tuned Whisper-small, but this hurt MER on out-of-domain internal sets: Internal-1 5.9 → 7.7–14.7. The authors' recommended setup keeps Whisper **frozen** and runs the KWS as a separate module (it needs its own Whisper encoder pass) — [peer-reviewed] [Li et al. 2024](https://arxiv.org/abs/2309.09552)
- CB-Whisper results, frozen Whisper-large-v2 + OV-KWS + spoken-form prompt (MER% / entity recall%): Internal-1 4.4/87.3 → **2.9/97.7**; Internal-2 5.6/79.9 → **3.6/96.9**. Naive prompt: 4.7/97.4 and 6.6/95.1, so recall is similar but MER is worse than with no prompt. KWS F1 0.83–0.90. Test sets hold 150–371 entities over 99–1,334 utterances. Footnote: "experiments with the Whisper-large-v3 model … did not outperform the v2 model" — [peer-reviewed] [Li et al. 2024](https://arxiv.org/abs/2309.09552)
- With an oracle ground-truth entity prompt, Whisper-small entity recall on Aishell-dev rose 6.3 → 81.6% (MER 16.7 → 13.3). Prompting only the relevant entities is very effective when the selector is right — [peer-reviewed] [Li et al. 2024](https://arxiv.org/abs/2309.09552)
- **Bias-word ranking scorer** (SJTU): TTS (edge-tts) for bias words, Whisper-large-v3 encoder features projected 1280→368, dual cross-attention, 4 similarity matrices, a 4-layer CNN, then top-k selection. It was trained on LibriSpeech train-clean-100 with 40% edit-distance hard negatives. Whisper-turbo + prompt + scorer (top-50, true words last), B-WER test-clean/test-other: N=100 5.4/10.0; N=500 5.4/10.7; N=1000 5.6/11.3; N=2000 5.8/11.7. Prompting the raw list gave 7.8/15.2 (N=100) to 9.8/19.5 (N=2000), against a no-prompt baseline of 10.4/19.7. On a 4,365-word NER list: top-10 B-WER 13.51/19.46, **top-50 11.51/17.74 (best)**, top-100 and top-200 12.92/18.64, baseline 16.70/25.15 — [peer-reviewed] [Hou et al. 2025](https://www.isca-archive.org/interspeech_2025/hou25_interspeech.pdf)
- **KG-Whisper** (aiOla): a frozen AdaKWS open-vocabulary spotter picks keywords that are placed between `<|startofprev|>` and `<|startoftranscript|>` with `|` delimiters. Plain prompting of a frozen Whisper with these keywords *hurt* WER on 2 of 3 sets (see Q1). Fixing that required decoder fine-tuning (906M params) or prompt-tuning (15K params). Training ran 30K steps on VoxPopuli — [preprint] [Shamsian et al. 2024](https://arxiv.org/abs/2406.02649)
- **H-PRM** (Kuaishou, CIKM 2025): phonemic-embedding retrieval of the top-N hotwords by acoustic similarity, then a CB-Whisper-style spoken prompt to Whisper-small. Aishell-dev MER 16.24 → 9.88 and post-recall rate 36.84 → 86.98% (OV-KWS: 14.54 / 51.23). Common-Voice-en MER 9.78 → 7.60. The authors state that existing models' "recognition rate drops dramatically with the number of hotwords increasing" — [peer-reviewed] [Dai et al., CIKM 2025, arXiv:2508.18295, doi:10.1145/3746252.3760880](https://arxiv.org/abs/2508.18295)
- **CTC-assisted selection** (an LLM-based ASR, not Whisper): a coarse CTC hypothesis filters the hotwords, which are then prompted. B-WER test-clean 3.67 (N=100) → 4.41 (N=2000), against 9.33 with no bias and 2.78 with oracle hotwords. Removing common words before matching, and matching each word to its most similar hotword, reduced false matches of bias words to similar common words — [peer-reviewed] [Yang et al., SLT 2024, arXiv:2411.06437](https://arxiv.org/abs/2411.06437)

### Inferences
- A **training-free approximation** for your setting: (1) first pass without hotwords, or with a generic list; (2) fuzzy-match a large departmental term dictionary (hundreds to thousands of terms) against the first-pass text per lecture or per window, using jamo- or pronunciation-level edit distance; (3) re-decode with the top ~20–40 matched terms as `hotwords`. This mirrors CTC-assisted filtering (Yang 2024) and the top-k finding (Hou 2025: k≈50 optimal for English; k=10 already captures about 60% of the k=50 gain). Costs: about 2× decoding time, and selection recall is limited by first-pass errors. Terms the first pass mangles beyond fuzzy-match distance stay unrecovered. (Interpretation; not tested in any cited paper with Whisper.)
- Per-window hotword lists in faster-whisper mean calling `transcribe()` per clip (or with `clip_timestamps`), since `hotwords` is fixed per call. Issue #1313's maintainer reply suggests nothing more dynamic exists ([#1313](https://github.com/SYSTRAN/faster-whisper/issues/1313)). (Interpretation.)
- Training a CB-Whisper/Hou-style scorer for Korean would need Korean TTS (CosyVoice and GPT-SoVITS support Korean according to Liu et al. 2025) and some labeled data. That is a "near-term no" under your constraints, but it is the strongest path once fine-tuning becomes possible.

### Gaps
- No published per-utterance latency or VRAM figures for CB-Whisper/H-PRM selectors. Fit on a single RTX 2070 alongside large-v3 int8 is unknown.
- No KWS-then-prompt results for Korean or for long-form lecture audio. All results are short utterances (Aishell, LibriSpeech, internal talks segmented to utterances).
- CB-Whisper does not report KWS candidate-list size, so its robustness to thousands of candidates is untested ("future work: … handle a large keyword database").

## Q3. Trained biasing modules vs decoding-time boosting: which can be applied to Whisper at inference only?

### Takeaway
CLAS, deep biasing, contextual adapters and TCPGen all need training. TCPGen can be bolted onto a **frozen** Whisper but needs task data and a custom decoder loop. Inference-only options are (a) prompting, and (b) shallow-fusion **trie/boosting-tree rewards** in beam search with revocation of partial matches. On Whisper-large-v3, (b) cut LibriSpeech B-WER by 38–43% with 1,000 distractors without hurting U-WER, so it scales far better than prompts. Neither faster-whisper nor CTranslate2 exposes a documented per-step logit hook, so (b) means changing the decoder.

**Supporting details**
- Liu et al. ablation on Whisper-large-v3, LibriSpeech, N=1000 distractors, beam 10: "final-token-only" reward gives B-WER 7.95/13.61 (clean/other). The uniform per-token reward with revocation ("if at any point the next expected token does not match, the awarded reward is immediately removed") gives 6.11/10.52. Multi-pronunciation variants **without** syllable filtering gave WER 19.97/26.45 because of noisy variants. The final system S7 cut WER 18% and 21% and B-WER 43% and 44% (test-clean/test-other) "without any fine-tuning or reliance on large language models" — [peer-reviewed] [Liu, Peng, Chng, APSIPA ASC 2025, arXiv:2508.17796](https://arxiv.org/abs/2508.17796)
- Sun et al.: TCPGen reads Whisper's final decoder hidden state; "the entire Whisper model is frozen and only parameters in TCPGen are updated"; the training biasing list is error-based (words decoded with above-average error). Average relative R-WER reductions: 20% (LibriSpeech), 28% (SLURP), 42% (DSTC2) for base.en, larger with large. "Contextual biasing was more effective when applied to domain-specific data". Code: [BriansIDP/WhisperBiasing](https://github.com/BriansIDP/WhisperBiasing) — [peer-reviewed] [Sun et al., Interspeech 2023, arXiv:2306.01942](https://arxiv.org/abs/2306.01942)
- Kwok & Yip: naive trie biasing "biases both tokens '[Bon]' and '[Bu]' with equal rewards". Score revocation "requires computationally expensive beam search and does not work in the greedy decoding scenario". Trie rewards tuned for small beams "may cause over-biasing for larger beam sizes". In their setup, contextual adapters and TCPGen gave no improvement on top of a synthetic-data fine-tuned Whisper-small — [peer-reviewed] [Kwok & Yip, Interspeech 2025, arXiv:2509.09196](https://arxiv.org/abs/2509.09196)
- Nguyen et al.: trie boosting alone (no prompt) on Whisper-M gave HGP CER 14.66 (vs 14.97); combining it with the initial prompt was best (11.57). Automatically built dictionaries (Whisper errors minus common words) did slightly worse than human dictionaries (Whisper-M combined avg CER 13.49 vs 10.95). Whisper-large was not reported "due to very tiny improvements" — [peer-reviewed] [Nguyen et al., SIGDIAL 2024](https://aclanthology.org/2024.sigdial-1.42.pdf)
- Pundak et al.: "When thousands of phrases are presented to CLAS, retrieving a meaningful bias context vector becomes challenging … might be far from any context vector seen in training"; CLAS "degrades on the Talk-To set which has thousands of phrases" until bias-conditioning is added — [peer-reviewed] [Pundak et al., SLT 2018, arXiv:1808.02480](https://arxiv.org/abs/1808.02480)
- Alon et al.: using "phonetically similar phrases as negative examples" during CLAS training gives "up to 53.1% relative improvement in word error rate" — [peer-reviewed] [Alon, Pundak, Sainath, ICASSP 2019, arXiv:1810.12170](https://arxiv.org/abs/1810.12170)

### Inferences
- **For off-the-shelf faster-whisper today, only prompting and selection-then-prompting are usable without touching the decoder.** Trie boosting with revocation is the most promising next step: training-free, deterministic, and on Whisper-large-v3 it held up at N=1000 where prompting gave nothing. It needs a beam-search loop that can add rewards per hypothesis. Practical routes: (i) patch or reimplement beam search over CTranslate2 per-step logits, (ii) run large-v3 via HF transformers with a custom `LogitsProcessor` (slower and heavier on 8 GB), or (iii) openai-whisper's decoder, whose `LogitFilter` interface could host a trie reward. All three need engineering and benchmarking on your GPU. (Interpretation.)
- **The 간염 [가념] vs 감염 case is the textbook failure for every method above.** The prompt only shifts a prior and "will not override the model's comprehension of the audio" (OpenAI guide). 감염 is far more frequent, and the two words differ by one nasal coda (ㄴ vs ㅁ) after liaison. A trie or boost strong enough to flip 감염→간염 would also flip true 감염 tokens, which is exactly the false-biasing of a common word that distractor experiments penalize (U-WER). CTC-WS and TurboBias explicitly exclude very short entries for this reason. CLAS-family models needed *trained* hard negatives to separate phonetically similar items (Alon 2019). A context-conditioned decision (e.g., "B형/C형/만성/급성 ___", "___ 바이러스") is more likely to work as targeted post-correction or N-best rescoring than as model-side biasing. (Interpretation, beyond the scope of model-side methods.)
- TCPGen and CLAS-type modules are off the table under "no training in the near term", but TCPGen's frozen-Whisper design makes it the most portable trained option later. Sun et al.'s error-based biasing-list construction (decode the training data, keep words with above-average error) is reusable now for choosing hotwords. (Interpretation.)

### Gaps
- I did not verify whether CTranslate2's `Whisper.generate` (used by faster-whisper) exposes any per-step logits callback. My understanding is that it does not, but this is unconfirmed and should be checked against the CTranslate2 docs before planning a trie implementation.
- No published trie-boosting result for Korean, and none for long-form lecture audio with Whisper.
- Contextual adapters (Amazon) were not examined in primary sources here, apart from Kwok 2025's negative reproduction.
- Vendor "keyword boosting" limits (AssemblyAI `word_boost`, Deepgram keywords) were not fetched. No practitioner list-size caps are reported here.

## Q4. How does biasing-list size (and distractors) change accuracy?

### Takeaway
Every method loses bias-word accuracy as distractors grow, but at very different rates. **Plain Whisper prompting collapses fastest**: about 25% B-WER reduction at N=100 shrinks to almost nothing at N≥500, partly because the list overflows the 224-token window. Trained or structural methods degrade gently: TCPGen loses about 10% relative from N=100 to N=2000, and WFST shallow fusion is nearly flat. Selecting a top-k subset (k≈10–50) restores most of the gain. Standard benchmark sizes are N ∈ {100, 500, 1000, 2000} distractors on the LibriSpeech IS21 rare-word list (209.2K rare words; about 10% of test tokens are rare).

### Cited Findings
- **Benchmark protocol**: IS21 list = all LibriSpeech words outside the 5,000 most frequent (≈209K "rare" words). Per utterance, the list is the reference rare words plus N random rare-word distractors, N ∈ {100, 500, 1000, 2000} — [peer-reviewed] [Le et al., Interspeech 2021, arXiv:2104.02194](https://arxiv.org/abs/2104.02194). Rare words are about 10.96% (test-clean) and 10.22% (test-other) of tokens, about 2.2 and 1.83 per utterance — [peer-reviewed] [Liu et al. 2025](https://arxiv.org/abs/2508.17796)
- **Whisper-turbo prompt, B-WER test-clean/test-other by N** (baseline 10.4/19.7): N=100 7.8/15.2; N=500 9.5/19.1; N=1000 10.0/19.3; N=2000 9.8/19.5. With top-50 scorer selection: 5.4/10.0 → 5.8/11.7. TCPGen-Whisper: 11.0/19.3 (N=100) → 12.0/21.1 (N=2000). Authors: "as the bias list size increases to N ≥ 500, the reduction in B-WER becomes negligible"; TCPGen is more robust but "still experiences a relative decline of about 10%" — [peer-reviewed] [Hou et al. 2025](https://www.isca-archive.org/interspeech_2025/hou25_interspeech.pdf)
- **Top-k curve on a 4,365-entity NER list** (Whisper-turbo prompt, B-WER test-clean): k=0 16.70; k=10 13.51; **k=50 11.51**; k=100 12.92; k=200 12.92. The gain peaks at k=50 and falls past it — [peer-reviewed] [Hou et al. 2025](https://www.isca-archive.org/interspeech_2025/hou25_interspeech.pdf)
- **Fine-tuned prompt-biasing Whisper** (B-Whisper) vs Whisper+P at list sizes 35/70/150: "both models suffer from degradation in R-WER as biasing list size increases, as the number of false-bias words has increased". Whisper+P is capped at 70 by the 224-token limit. With **only false-bias words** in the list, WER *decreased* from N=35 to N=70 for both models (exact values only in Fig. 2) — [preprint] [Jogi et al. 2025](https://arxiv.org/abs/2502.11572)
- **TCPGen + Whisper base.en on SLURP**: R-WER 72.5% (no biasing) → 52.3% (1000 distractors) → 60.5% (full 5.6k list), still 18% relative better than baseline at full size. Fig. 2 sweeps 100/200/500/1000/2000/Full. Exact per-point values are only in the figure — [peer-reviewed] [Sun et al. 2023](https://arxiv.org/abs/2306.01942)
- **RNN-T deep biasing vs WFST shallow fusion** (LibriSpeech, B-WER test-clean, baseline 14.1): DB-RNNT 9.8 (N=100) → 10.7 → 11.0 → 11.4 (N=2000); WFST 9.4 → 9.6 → 9.7 → 9.6; WFST+DB-RNNT 7.4 → 8.1 → 8.5 → 8.9. "the B-WER improvement … gets progressively smaller as the biasing list gets larger" because DB-RNNT was trained with 400–800 distractors. Sampling more training distractors helps large lists but hurts small ones: "the number of distractors sampled during training should be based on the expected biasing list size in testing" — [peer-reviewed] [Le et al. 2021](https://arxiv.org/abs/2104.02194)
- **Trie biasing on a fine-tuned Whisper-small** (NSC-2 Singapore English), B-WER by distractors: N=10 21.12, N=50 23.03, N=100 24.91 (unadapted 55.80; fine-tuned without biasing 29.66). "its effectiveness diminishes as N increases, likely because the method biases to the wrong rare words". K-step prediction flattens this to 20.93 → 21.84 — [peer-reviewed] [Kwok & Yip 2025](https://arxiv.org/abs/2509.09196)
- **Trie biasing on frozen Whisper-large-v3** at N=1000: B-WER 9.86 → 6.11 with U-WER 1.94 → 1.87 (test-clean). The paper reports only N=1000, no sweep — [peer-reviewed] [Liu et al. 2025](https://arxiv.org/abs/2508.17796)
- **CTC word spotter**: list 100 → 250 → 500 → 750 → 1000 words, F-score 0.870 → 0.864 → 0.852 → 0.845 → 0.845; precision 0.892 → 0.834 (recall roughly flat 0.850–0.856); WER 10.48 → 10.73; decode time 15 → 26 s — [peer-reviewed] [Andrusenko et al., Interspeech 2024, arXiv:2406.07096](https://arxiv.org/abs/2406.07096)
- **GPU phrase-boosting tree**: expanding the list from 200 to 20K LLM-generated terms was "relatively robust", with the boosting weight reduced 1 → 0.7 "to avoid a large number of false accepts" — [preprint] [Andrusenko et al. 2025, TurboBias, arXiv:2508.07014](https://arxiv.org/abs/2508.07014)
- **CTC-assisted LLM-ASR with filtering**: B-WER test-clean 3.67 (N=100), 3.92 (500), 4.16 (1000), 4.41 (2000) — [peer-reviewed] [Yang et al. 2024](https://arxiv.org/abs/2411.06437)
- **Shallow fusion in general**: these methods "can degrade WER/U-WER performance when the bias list becomes large, due to an increase in false positive distractor terms with similar spellings or pronunciations" — [peer-reviewed] [Liu et al. 2025](https://arxiv.org/abs/2508.17796)

### Inferences
- For prompting, the useful regime is **≤ ~50–70 well-chosen terms that fit within 223 tokens**. Your 42-term / 223-token list is already at that ceiling. Adding terms in faster-whisper silently drops the tail rather than diluting, so "bigger list" means "different list". Gains are better pursued by *choosing* terms per lecture than by adding them. (Interpretation.)
- Distractor evidence suggests limiting a term's list membership to lectures where it is plausible: per-course or per-week lists, not one global list. Unused terms act as distractors that raise false-insertion risk and consume budget. (Interpretation.)
- An empirical curve for your data would come from fixing a lecture set and sweeping list size (e.g., 10/20/40 terms, plus irrelevant terms from other courses as distractors), measuring tracked-term errors, untracked WER, and insertions of listed terms. No literature covers Korean lectures. (Interpretation.)

### Gaps
- No published list-size sweep for faster-whisper `hotwords` or for any Whisper prompt in Korean.
- Exact per-N values for Sun et al. (Fig. 2) and Jogi et al. (Fig. 2) are only plotted, not tabulated.
- No study separates the "token overflow/truncation" effect from the "attention dilution" effect for Whisper prompts.

## Q5. Results for Korean or other agglutinative / non-English languages

### Takeaway
There is **no peer-reviewed contextual-biasing study on Korean Whisper** that I could find. The nearest evidence: Japanese (trie + prompt works, large gains on in-house jargon), Mandarin/code-switch (CB-Whisper, H-PRM), and European languages where **plain prompting hurt** (French/German). A Korean domain study (meteorology) shows zero-shot Whisper struggles with Korean technical terms and that TTS-based fine-tuning, not prompting, closed most of the gap.

### Cited Findings
- **Japanese** (agglutinative): trie boost + initial prompt on Whisper-M cut HGP (incident reports, 150 jargon terms) CER 14.97 → 11.57, and lifted GPT-Syn DRR 16.95 → 82.37 and JNAS DRR 28.35 → 46.26. Example fix: 流分 (non-word) → 留分 — [peer-reviewed] [Nguyen et al., SIGDIAL 2024](https://aclanthology.org/2024.sigdial-1.42.pdf)
- **Mandarin / zh-en code-switch**: CB-Whisper (see Q2) and H-PRM (Whisper-small Aishell-dev MER 16.24 → 9.88) — [peer-reviewed] [Li et al. 2024](https://arxiv.org/abs/2309.09552); [Dai et al. 2025](https://arxiv.org/abs/2508.18295)
- **European languages, plain prompting (N=70)**, WER: French 8.3 → 10.8, German 6.3 → 15.2, Spanish 4.4 → 5.9, Italian 12.9 → 13.6. "contextual biasing via prompting is effective in Whisper for English, it proves ineffective for certain non-English languages such as French and German". The fine-tuned B-Whisper+P improved all four (fr 5.5, de 5.5) — [preprint] [Jogi et al. 2025](https://arxiv.org/abs/2502.11572)
- English prompts beat Mandarin prompts even on Mandarin speech, "likely due to differences in training data distributions" — [preprint] [Yang et al. 2024](https://arxiv.org/abs/2406.05806)
- Visual (word-list) prompting helped English-only Whisper but **hurt multilingual Medium/Large/Large-V2**; the authors suspect multilinguality — [peer-reviewed] [Peng et al. 2023](https://arxiv.org/abs/2305.11095)
- **Korean meteorological ASR** (KAIST): zero-shot Whisper-large-v2 CER 14.66 (KsponSpeech eval) vs 18.35 (WeatherTest), sWER 25.46. Fine-tuning on KsponSpeech did not help domain terms (WeatherTest CER 24.57). Fine-tuning on TTS-generated weather queries reached CER 10.64. LLM post-correction gave inconsistent gains. The authors cite "the language's agglutinative structure and specialized" terms as difficulties — [preprint] [Park, Cho, Choo 2024, arXiv:2410.18444](https://arxiv.org/abs/2410.18444)
- **Korean hotwords in faster-whisper**: hallucinated Korean hotword phrases on silent input — [practitioner] [faster-whisper #1356](https://github.com/SYSTRAN/faster-whisper/issues/1356)
- TTS engines with Korean support used in biasing pipelines: CosyVoice and GPT-SoVITS (5 languages incl. Korean), per Liu et al. — [peer-reviewed] [Liu et al. 2025](https://arxiv.org/abs/2508.17796)

### Inferences
- Your own result (352 → 137 tracked errors with 42 Korean terms) is positive evidence that prompt biasing *does* work for Korean on large-v3. That contrasts with the French/German degradation reported for prompts. Because the European results came with *overall* WER increases, the open question for you is untracked-word WER and insertions, not tracked-term gains. (Interpretation.)
- Korean-specific factors that likely matter (interpretation, not tested in literature): (1) **token cost** (2–10 BPE tokens per term) cuts the effective list to about 40 terms, against about 70 English words. (2) **Particle attachment**: a hotword "간염" must still match "간염은/간염이" in decoding, which suits prompting (soft) better than exact-match trie boosting (token sequences differ at the boundary). (3) **Liaison and nasal assimilation** (간염 [가념] vs 감염 [가몀]) create near-homophones with a frequent competitor, which no inference-time biasing method handles well (see Q3 inferences). (4) **Transliterated loanwords and English abbreviations**, which you saw fixed well, match the "rare word with no strong in-vocabulary competitor" case where all biasing literature reports its largest gains.
- For Korean trie biasing, reward units should probably be defined over Whisper's byte-level BPE tokens of the canonical spelling *plus* common particle-attached variants, or the reward should be revoked only at eojeol boundaries. That is a design question with no published answer. (Interpretation.)

### Gaps
- No Korean contextual-biasing benchmark (no IS21-style rare-word list for KsponSpeech) and no Korean distractor experiments were found.
- No study of Whisper prompt biasing on near-homophone pairs created by Korean phonological rules (연음, 비음화).
- Korean-language results for KWS-then-prompt or trie boosting with Korean TTS were not found.
