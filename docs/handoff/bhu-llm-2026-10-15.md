## 1. 요약

- 운영자는 bhu-llm 연구 보고서 모드에서 교수·직원이 녹음을 올려 전사록과 그 정리(회의록·강의록)를 받게 하려 한다. 전사는 stt 가 교내
  서버 GPU 에서 하고, bhu-llm 은 맡기기·상태 보기·결과 받기만 한다.
- 지금 stt 는 운영자의 명령줄 도구다. 서버에서 맡은 일을 받아 처리하는 방식, 결과 약속, 서버 배포가 없다.
- **가장 먼저 볼 것은 용어 사전 한도(S9)다.** 운영자의 2026-10-15 전사 작업 기록: 「기존 terms.txt: 137개, 818토큰이라 앞쪽 약 3분의 1만
  실제로 반영되고 있습니다. 이번 작업 범위 밖이라 손대지 않았습니다.」 원인은 아래 §3 S9 에 있다. bhu-llm 과 상관없이 지금 명령줄
  사용에도 해당한다.

## 2. 운영자 결정 (2026-10-15) — stt 에 걸리는 것

| # | 결정 | stt 에 주는 뜻 |
|---|---|---|
| 1 | bhu-llm 에서는 연구 보고서 모드에서만 부른다 | 이용자 수가 적다(`report-authors`, 14명). 처리 단위는 한 번에 하나로 충분하다 |

## 3. stt 할 일

| ID | 할 일 | 구분 |
|---|---|---|
| S9 | **용어 사전 한도.** `load_terms` 는 용어를 `, ` 로 이어 faster-whisper 의 `hotwords` 로 넣는다(`src/stt/transcribe.py:184-219`, `:529`). faster-whisper 1.2.1 은 hotwords 를 `max_length // 2 - 1` = 223 토큰에서 자른다(`faster_whisper/transcribe.py:1546-1547`, `max_length = 448` — `:722`). stt 는 `condition_on_previous_text=False`(`src/stt/transcribe.py:528`)라 프롬프트는 hotwords 뿐이다. 그래서 818 토큰짜리 `terms.txt`(137개)는 앞쪽 223 토큰 — 약 27%, 대략 앞쪽 37개 — 만 반영되고 나머지는 **말없이** 버려진다. 권고: ① 넘치면 경고하고 반영된 용어 수를 출력·`.meta.yaml` 에 남긴다(최소) ② 한도 안으로 고르는 방법(과목별 사전 분리, 우선순위, 구간별 선택 등)은 stt 가 정한다. bhu-llm 은 확인 창에 「반영되는 용어 N개 / 전체 M개」를 보이려 하므로 그 값을 결과에 담아 주기를 바란다 | 즉시 |
| S1 | **처리 단위.** 요청함의 작업을 하나씩 꺼내 전사하는 상주 단위(systemd). GPU 작업은 한 번에 하나(RTX 2070 8GB 한 장 — 운영자의 손 전사와 같은 GPU). 대기·진행(진행률)·완료·실패 상태를 파일로 낸다. 모양은 geo-scout 요청함(`/var/lib/geo-scout/requests/{inbox,outbox}`)을 참고 | 선행 |
| S2 | **작업·결과 약속(JSON Schema).** 작업: 원본 파일, 언어, 단어장(작업에 딸린 파일), 화자 구분 여부, 요청자 표식, 원본 삭제 시기. 결과: 상태, 전사록(txt — `[MM:SS]` 문단, 화자 구분 시 `[MM:SS] 화자N:`), srt, 머리글, 실행 요약(모델·장치·녹음 길이·소요·반영된 용어 수), 오류 이유. 스키마를 stt 클로저에 실어 bhu-llm 이 검증하게 한다 | 선행 |
| S3 | **Nix 패키지와 NixOS 모듈.** 지금 의존성은 uv 의 manylinux 바퀴(ctranslate2·onnxruntime·av)다. 서버 단위로 돌리려면 Nix 로 묶는다. Whisper·pyannote 모델은 미리 받아 두고 실행 중에는 망을 쓰지 않는다 | 선행 |
| S4 | **원본 삭제.** 원본과 그 파생 음성(추출한 wav 등)을 작업의 삭제 시기에 지운다. 어떤 상태든 받은 뒤 24시간을 넘기지 않는다(실패·멈춘 작업 포함). 처리 중 원본은 암호화된 곳에만 둔다(서버의 큰 디스크 둘은 평문이다 — bhu-llm 대장 F193) | 선행 |
| S5 | **한도.** 최대 크기(100MB)·길이, 작업당 시간 상한. 실패하면 일부 결과를 완전한 것처럼 내지 않는다 | 선행 |
| S6 | **작업별 단어장.** 단어장은 작업에 딸려 오고 작업과 함께 지워진다. 서버에 이용자 단어장을 쌓지 않는다 | 선행 |
| S7 | **화자 구분 배포.** pyannote(`src/stt/diarize.py:33`), torch, 게이트 모델 접근용 `HF_TOKEN`(agenix). 서버 경로에서는 `화자N` 표시만 하고 `--voice-db`·`stt enroll` 을 쓰지 않는다. 화자 구분 포함 처리 시간을 잰다 | 선행 |
| S10 | **화자 번호의 일관성.** 실명이 없으므로 한 전사록 안에서 같은 사람은 끝까지 같은 `화자N` 이어야 이용자가 나중에 이름을 일괄로 바꿀 수 있다. 짧아서 확신이 없는 구간(`(?)`, `--min-speaker-seconds`)의 표시 방식을 결과 약속에 적는다 | 선행 |
| S11 | **「지금 지우기」.** 완료 뒤 이용자가 바로 지우라고 하면 원본·파생 음성·단어장 사본을 즉시 지우는 요청을 받는다. 지운 사실을 결과에 남긴다 | 선행 |
| S8 | **영상 처리와 장면 사진.** 영상에서 음성 추출, 지목한 시각의 장면 사진(bhu-llm 대장 A18) | 뒤 단계 |
| S12 | **기록 정리.** README 는 머리글 양식을 `template_version` 1.1 로, 코드는 1.3 으로 적었다(`src/stt/metadata.py:5-6`). `terms_microbiology.txt` 가 미추적 상태다 | 즉시 |

- bhu-llm 은 「선행」 항목이 끝나 배포되기 전에는 stt 를 부르지 않는다(geo-scout 와 같은 원칙).

## 4. 삭제 시기 — bhu-llm 세션 제안, 운영자 확인(2026-10-15)

- 접수 확인 창에서 묻는다: [전사가 끝나면 바로 삭제] / [오늘 자정까지 보관 — 그 사이 같은 녹음으로 다시 전사할 수 있음].
- 「바로 삭제」면 완료 즉시 지운다. 「보관」이면 자정(00:00, KST)에 지우고, 결과 안내에 「원본 녹음은 오늘 24:00 에 삭제됩니다」를 적는다.
  보관 중에도 「지금 지워줘」 하면 바로 지운다(S11).
- 어떤 경우에도 받은 뒤 24시간을 넘기지 않는다(S4).
- 「대화가 끝나면 삭제」는 쓰지 않는다. 대화가 끝났다는 신호가 없다(이용자는 창을 닫을 뿐이다).
- 단어장 사본과 내려받기용 파일(전사록·단어장)도 같은 자정에 지운다. 전사록 본문은 대화 안에 남고 대화 보존 규칙을 따른다(bhu-llm 쪽).

## 5. bhu-llm 이 부를 때의 조건

| 항목 | 값 |
|---|---|
| 통로 | 요청함 파일(비동기). bhu-llm 의 OWUI 단위가 inbox 에 작업과 원본을 넣고 outbox 를 읽는다. 상주 HTTP 서비스는 두지 않는다(권고) |
| 원본 위치 | 교내 서버 안. 원본·파생 음성은 밖으로 나가지 않는다. 밖(해외 모델)으로 가는 것은 전사문뿐이다 |
| 응답 | 접수 즉시 접수 번호와 대기 순서. 완료는 이용자가 다시 물어 확인한다(1단계) |
| 실명 | 없음. `화자N` 만 |
| 단어장 | 작업마다 받는다. 반영된 용어 수를 돌려준다 |
